# Cues: a Capability the model cannot see is one it cannot reach for

BeanBot made Clips nobody asked for — on plain questions, on follow-ups after one legitimate Clip, piled onto requests for something else entirely, and on ordinary words like "tell" and "announce". A Capability may now declare **Cues**, words a Trigger must contain before it goes **On Offer** at all. Speech declares them; everything else is always On Offer, which is the zero value.

## Considered Options

**What licenses a Clip.** The rule chosen is the narrowest one available: the Trigger itself must ask. A standing licence — a request anywhere in the Backlog, good until the conversation moves on — was rejected because that *is* the momentum failure, dressed as a feature: nobody can state when the licence expires, and BeanBot's own Clips sit in the Backlog as the evidence that speaking is what it does here. A per-Guild switch a mod flicks was rejected for reversing ADR 0005's "nothing new is configurable" to solve a problem that is not about which servers want speech; every server wants it sometimes.

**Where the check lives.** Refusing the call in Go — one more reason `agent.invoke` says no, alongside the Gate and the budget — was rejected in favour of withholding the declaration. Three reasons, in ascending order of weight. It is cheaper: the declaration is a description, six voices with their characteristics, an enum and a style direction, roughly 180 tokens on every Trigger in every server for a tool wanted on a small fraction of them. It is kinder when the check is wrong: a false negative leaves BeanBot answering in text, rather than telling somebody who *did* ask that they did not. And it is the only limit here that a poisoned Memory cannot argue with — not because the argument fails, but because there is nothing to argue about. ADR 0005 put the length cap in Go on the reasoning that Memory is member-writable and injected into every prompt, so "always speak for as long as you can" is a durable instruction a prompt-side limit loses to. "Always speak, whether or not they asked" is the same attack against a tool description. A tool that was never declared has no description to talk around.

**How Go recognises the ask.** A model call to classify each Trigger was rejected on the shape ADR 0005 already rejected for the voice catalogue: a cost on ~100% of Triggers to serve a tool wanted on ~2% of them, and here a round-trip of latency too, in front of every reply BeanBot makes. A literal marker — "out loud" or nothing — was rejected as undiscoverable: it is learned by word of mouth or not at all. The Cues are a hardcoded list of words that can only mean sound. `say`, `tell` and `announce` are deliberately **not** among them: they are how people ask for ordinary answers, and admitting them keeps the fourth failure exactly as it was.

The list is generous within that constraint, because a Cue is a *necessary* condition and not a decision. Going On Offer is not being called; the tool description still does the precision work, and the model still declines. This is what makes the narrowness affordable — the cost of a Cue that is slightly too broad is one wasted mention in a prompt, while the cost of one too narrow is a request that silently fails.

**What counts as the Trigger.** Its own text, or a reply to one of BeanBot's own audio attachments. The second is not a word-guess at all but a fact about the message: somebody hit reply on a Clip. It buys "again, but angrier", which is the one natural phrasing the rule otherwise breaks and the one nobody would think to rephrase. It does mean that replying "lol" to a Clip puts speech back On Offer with only the description holding it — accepted, because pointing at audio is a much narrower act than the momentum this replaces, where any later message in the channel would do.

**How general.** A special case where declarations are assembled was rejected in favour of a method on `Capability`, the same move ADR 0005 made with `Medium()`. Images have the same shape of exposure — declared on every Trigger, ungated, and five times the price — and are not Cued here only because nobody has reported them misfiring. When somebody does, it is a word list, not a refactor. Cueing every Capability was rejected outright: recording a Memory is passive by design, nobody ever asks BeanBot to remember anything, and a Cue on it would mean it never ran.

**Telling the model it can speak anyway.** A line in `situate` — twenty tokens against the declaration's 180, keeping BeanBot honest and teaching the phrasing — was rejected for a failure mode worse than the one it fixes. A model that believes it can speak but holds no tool to do it will claim to have posted a Clip that does not exist. BeanBot denying it can do voices is wrong and recoverable; BeanBot announcing a Clip that never arrives is wrong and looks broken.

## Consequences

- `Trigger` in `CONTEXT.md` said "BeanBot never speaks uninvited", where *speaks* meant *posts at all* — one glossary holding that alongside `generate_speech`, `Clip` and `Voice`, where *speak* means *makes a sound*. It now reads "never answers uninvited", and speak, aloud and voice mean sound throughout. The conflation was not merely untidy: an invitation to reply was being read as an invitation to speak aloud, which is the bug in one sentence.
- Declarations are assembled per Trigger rather than precomputed once in `newAgent`, and the Trigger's own text and its reply target have to reach that assembly. A hallucinated call to a withheld Capability needs no new handling: `agent.invoke` already answers "there is no capability called %q".
- Two requests are now known to fail. "say it louder" is excluded by the decision not to Cue on `say`. "do that in a scottish brogue" fails because `brogue` is not a word anyone thought of, which is the standing cost of a hardcoded list — every phrasing somebody actually uses is a code change.
- BeanBot will sometimes tell people it cannot do voices. It has no way to know otherwise.
- The Backlog renders Clips as `[audio: ...]` rather than `[file: ...]`. Legible precedent is safe now that precedent cannot be acted on without a Cue, and it is what lets "do that one again, out loud" resolve which one.
- **This narrows ADR 0005's case for a six-voice shortlist.** That ADR rested it on two arguments, and this one kills the first: the declaration no longer reaches the model on every Trigger, so the full catalogue is no longer a permanent per-conversation charge. Only the second still stands — that a model choosing between few labelled options chooses better than one facing many. The shortlist therefore widened to 22, one per distinct characteristic: Gemini publishes 30 voices but only 22 characteristics, and since the name is meaningless astronomy, the eight duplicates were options the model would pick between blind. _Superseded by ADR 0008, which removed the model's choice altogether and took the list to all 30 — with nothing reading the labels, a duplicate characteristic stopped being a reason to drop a voice._
