# Attribute a Claim to the message it was made in

Every Memory entry was stamped with `time.Now()` and the display name of whoever sent the Trigger, which dated the write rather than the claim and named a member who had said nothing about the subject. Both now come from the Backlog message the Claim was actually made in: the model names the line, and Go reads the speaker and the timestamp off Discord's own copy of it. This supersedes ADR 0003's consequence that every entry carries "the member who prompted it" — nobody prompts a Memory write, because BeanBot writes passively while answering something else, so the name that clause described never existed.

## Considered Options

**Who supplies the name and the date.** Go holds every message of the Backlog with its real author and timestamp; the model holds the knowledge of which one a Claim came from. Letting the model return the speaker and the date as text was rejected outright. It puts an unforgeable field — today's name comes from Discord and `identify` refuses to attach a snowflake to anything Discord did not state — behind a sentence a member can type, so "steve says the raid is off" gets Steve's name stamped onto a Claim Steve never made, in the file that exists to be the audit trail. It also asks for a date the model cannot see. The model therefore points and Go resolves: `said_in` is a line number, and everything written to the file is read from the message that line was rendered from.

**The handle.** A Discord snowflake on every line was rejected on cost and on transcription — nineteen digits across fifty lines, of the kind models copy worst. A bare ordinal was rejected on its failure mode: a miscount still resolves, to a real neighbouring message under a different real name, so it fails *open* into a plausible misattribution that nothing downstream can spot. That is the same unrecoverable class ADR 0004 refused when it rejected name-matching for snowflakes. The model therefore returns the ordinal *and* the speaker name it read, and Go refuses the call when they disagree. The name is a checksum and nothing more — it is compared against the line and then discarded, and what reaches the file is always Discord's copy.

**When nothing resolves.** Making the Source optional and falling back to the Trigger was rejected as the worst of the three: it reintroduces the original bug intermittently, leaving a file where correct and incorrect Attributions are interleaved with no way to tell them apart. A uniformly wrong file is honest by comparison, because nobody trusts it. A missing, out-of-range, self-citing or mismatched Source is therefore refused back to the model with something it can act on, exactly as a `replaces` that matches nothing already is. The cost is that a Claim occasionally goes unwritten. That is cheap: BeanBot writes passively, the conversation is still in the Backlog on the next Trigger, and ADR 0004's "nothing is forgotten" is a promise never to discard rather than a promise to catch everything.

**Citing itself.** BeanBot's own lines are numbered like any other and refused as a Source. Otherwise the loop closes: asked what it knows about Steve, BeanBot answers from its notes, then files its own reply as a fresh dated Claim — and a recollection that was wrong, or invented mid-sentence, is now on file twice looking independently attested. Nothing worth recording has BeanBot as its only possible source; anything true it says came either from the notes, where it already is, or from a member, whose message is the real line.

**Dates in the Backlog.** Attribution does not need them, since Go supplies the timestamp. They were added anyway, as a separator line whenever the day changes rather than a date on all fifty lines, because the Backlog showing only `[15:04]` against a "Current time" of today is a live defect this change made impossible to keep ignoring: the model cannot judge staleness it cannot see, and it resolves "let's do friday" from last Monday against this week.

**Claims, not facts.** The word `fact` was retired from the tool surface, the glossary and the Roster. What the file holds is that somebody said something on some day; whether it is true was never recorded and never could be. Until the Attribution named a real speaker the distinction had nothing to bite on, so `fact` was merely imprecise. Now that a Person's own account is visibly different from someone else's claim about them, calling both a fact throws away the difference at the moment it starts to matter.

## Consequences

- `renderBacklog` returns the ordinal-to-Source mapping alongside the text. Ordinals cannot be positions in the message slice, because rendering skips authorless and empty messages — deriving them separately drifts on exactly the Backlogs that have attachments and joins in them.
- Attribution now records one date, meaning when the Claim was made. When a line entered the file is no longer recorded anywhere, and the Memory has no history: it is one markdown file on one volume. Accepted, because getting a Claim into the file now requires saying it, which creates a real message with a real timestamp under your own name — the said-date is the one an audit wants.
- The recall framing in `situate` changes with it. Describing the notes as BeanBot's "own recollections" was harmless while every stamp named the Trigger's author and carried no information; against stamps that name real people it makes BeanBot assert hearsay about outsiders as its own knowledge, which is the failure ADR 0004 flagged and could not then address.
- A Person's own account of themselves is now distinguishable from a third party's claim about them, and `remember_person` asks for the subject's own line where more than one would do. Nothing in Go enforces that preference; it is guidance the model may ignore, and the Attribution is honest either way.
- Entries written before this change are grandfathered. They read as Claims made by the Trigger's author on the day of the write, which is wrong in a way no migration can fix — the messages they came from are long out of the Backlog. The file is markdown and hand-correctable over `fly ssh`, which was the point of ADR 0003's storage choice.
- Compaction rewrites the topical region through the model, and Attributions are now considerably more load-bearing than when it was written. Nothing yet stops a rewrite from scrambling or dropping them. Tracked as issue #2 rather than solved here.
