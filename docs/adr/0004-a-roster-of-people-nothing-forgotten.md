# A Roster of People that is never forgotten, and read back selectively

BeanBot keeps a Person entry for every human he learns something about — members of the Guild and outsiders alike — inside the same per-Guild Memory file, and he never discards from it. Because a Roster is unbounded where a document injected into every Trigger cannot be, Memory stops being read back whole: topical facts still are, but People arrive only when they are In Play, behind a Name Index of everyone else. This supersedes two things ADR 0003 settled — that the whole document goes into every Trigger, and that Compaction may rewrite all of it.

## Considered Options

**What a Person is.** A register — an entry created by *contact*, so that every member who ever spoke has a row — was rejected. Its growth tracks the Guild's headcount rather than what BeanBot has learned, it spends the budget on rows that teach the model nothing, and for the member half it is a worse copy of a list Discord already serves for free. A Person is therefore created by the first *fact*, with the bar deliberately low: "a guy goblin showed Facebook posts from" clears it, and a contentless name-drop does not. That bar lives in `remember_person`'s description and nowhere in Go, which has no basis to judge whether a fact is worth keeping and would be enforcing a rule the model cannot see.

**Its shape.** One line per person under `## People`, corrected by superseding the line, was rejected on the use case that prompted this: impersonating someone takes a paragraph of material, and a single line has to be retyped through the model on every update — the read-modify-retype pattern ADR 0003 already rejected for the document, merely scoped smaller. People instead get a heading each under `## People`, an identity line, and attributed fact bullets. Nesting them under `## People` rather than letting `## Steve Steveson` sit flat beside `## Traditions` costs a second level in the parser and buys the thing every later decision needs: *is this a Person, and which one* answerable in Go rather than inferred from a heading's spelling.

**Identity.** A Person is a canonical name plus a Discord snowflake when there is one — display names are the most mutable handle Discord offers, and keying on them alone means a nick change forks the entry and strands everything under a name nobody answers to. The snowflake is captured only where Discord stated it directly: the caller writing about themself, or an explicit mention resolved on the triggering message. Matching a name against Backlog speakers was rejected because it misfires exactly where it hurts — a Steve in the channel and a Steve on Facebook, silently declared one human. No ID is recoverable; a wrong ID is not, because nothing in the system will ever question it.

**Reading it back.** Injecting the whole document, as ADR 0003 did, caps the Roster at roughly sixteen people against the 8192-byte default. Raising the limit buys a linear multiple of that at a per-Trigger token cost, and postpones rather than answers. So People are injected only when In Play — named in the Backlog, or a speaker whose entry carries that snowflake — bounded by a byte budget filled most-recently-mentioned first. This introduces the retrieval ADR 0001 and 0003 both avoided, and its failure mode is real: BeanBot holds an entry he has no way to know he needs, when someone refers to a person without naming them. The Name Index is the mitigation: every Person reaches every Trigger, those In Play in full and the rest as a bare name at around twenty bytes each — so BeanBot can offer "you mean Steve Steveson?" instead of denying all knowledge, and the next Trigger's match loads the entry. A `recall` Capability closes the gap properly and is deliberately deferred: the storage shape is identical with or without it, so it can be added the day the Index is watched to fail, and until then neither its cost nor its necessity is known.

**Nothing is forgotten.** There is no `forget`, extending ADR 0003's position from an incidental consequence to the rule the Roster is built on. Compaction is the mechanism this collides with — it is a model rewrite of the only copy, and pointed at a roster it will merge two thin people or drop whoever has not come up in months, because that is what *make this smaller* means. Compaction is therefore confined to the topical region, which is prose and genuinely compressible; the Roster grows without a ceiling. That is affordable only because selective injection separated two numbers that used to be one: 8192 bytes was a *prompt* budget wearing a *storage* budget's clothes. A single Person too large for the injection budget is truncated newest-first with a visible marker, at read time — the file on disk stays whole.

**Duplicates.** Dedup on write is left to the model, which sees the Name Index every turn; Go silently redirecting a write to a heading the model did not name is the kind of clever that files facts under the wrong person with nothing to notice it by. Duplicates are therefore certain, and `merge_people` repairs them: every fact moves across and the absorbed name survives as an Alias. It is ungated, unlike a `forget` would have been, because it destroys nothing — the worst a malicious member achieves is welding two people together, which is visible in the file and repairable.

**Tool surface.** Overloading `remember` with an optional `person` argument was rejected: fields whose meaning depends on another field's value are the reliable way to get person facts filed topically, with Go unable to tell that from a deliberate write. `remember` keeps meaning *topical note* and loses its "who people are" clause; `remember_person` and `merge_people` are separate declarations where every field is always meaningful.

## Consequences

- "Nothing is forgotten" binds BeanBot, not the members. `remember_person`'s supersede still overwrites, so a member can still erase a fact by correcting it — what the rule guarantees is that BeanBot never discards on his own initiative.
- Durability is unchanged from ADR 0003 and now protects considerably more: a years-long Roster on one volume, one machine, no snapshots. Every mechanism here shields the Roster from BeanBot; none shields it from the volume. Accepted knowingly.
- The Roster is member-authored text about real people, including outsiders who cannot read or correct what is written about them. It stays where ADR 0003 put all Memory — in the user content, fenced and labelled as fallible notes, never in `SystemInstruction`, and unable to reach a Gate.
- The injected block now has three visibly distinct parts, and the Name Index must be labelled as *names known without details to hand*. Mislabelled, BeanBot denies knowing Steve while Steve's name sits in his own prompt.
- `BEANBOT_MEMORY_LIMIT` now bounds the topical region alone, and the injection budget is a second, separate number.
- Bullets orphaned directly under `## People` — from a hand edit, or from Compaction writing freely-shaped markdown — are tolerated: kept where they sit, injected on every Trigger rather than selectively, and never treated as a Person. This matches the parser's existing stance on stray prose: fold it in rather than drop it, because losing a recorded fact is the worse failure.
- Compaction is refused outright if it returns anything under `## People`. It is shown no People, so whatever it filed there is invented or a topical note it re-filed; since only its topical answer is kept, either way that text would disappear. Refusing leaves the notes oversized, which the next Trigger retries — the same trade the empty-result and grew-instead-of-shrank guards already make.
- `remember` refuses the reserved heading in Go rather than only being told not to use it, and the refusal names `remember_person`. A description alone leaves the failure silent and permanent: the bullet lands under `## People` belonging to nobody, where no name will ever find it.
- Matching ignores ordinary words *within* a name of several words, so an alias like "the Facebook guy" turns on "facebook" rather than on "guy". It does not ignore them when they are the whole name — somebody actually called Guy stays findable, since a noisy match costs bytes and an unfindable Person costs the entry.
